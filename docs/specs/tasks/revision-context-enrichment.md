# 补全局部修稿的创作上下文

## 任务目标

让 finding 驱动的局部修稿既能解决指出的问题，也能保持段间衔接、人物声音、作者风格和既定事实，避免把正文修得“正确但突兀”。

## 修稿输入

在现有 selected findings 和目标段落之外，按任务加入：

- 目标段落前后各 1–2 段，必要时扩展到同一场景边界；
- 本章合同与当前场景目标；
- 当前 POV 可见的事实、信念和不可使用信息；
- 作者风格宪法与少量相关作者样本；
- 与 finding 对应的方法模块；
- 不可改变的事实、必须保留的合同节点和作者明确要求保留的表达。

上下文按修稿目标裁剪，不无差别注入整章、全部作者样本或全部方法库。

## 输出与边界

继续输出独立修订候选，不直接覆盖草稿；继续复用段落 ID、三方合并和复检链路。模型只能修改获准段落，前后文仅用于衔接。

prompt 明确要求：

- 不新增未经正文支持的关键事实；
- 不改变 POV 知识边界；
- 不为消除 finding 而删除合同硬节点；
- 不抹平作者样本中具有辨识度的表达；
- 无法同时满足约束时返回失败，而不是静默扩大修改范围。

## 效果实验

通过 `revisionContext: legacy | enriched` 对比 finding 解决率、邻近段落衔接、人物声音、作者采用率和新增问题数。复检仍由独立调用完成，不能由修稿模型自证成功。

## 验收

- 假模型能验证 prompt 包含目标段前后文、合同、POV、相关方法和保留约束。
- 输出仍只能修改 selected findings 对应段落，合并与冲突语义不变。
- 前后文包含秘密时仍按 POV 规则处理，不因“只是上下文”而放行。
- 修稿后草稿哈希变化会使旧抽取和审计失效，现有行为保持。
- 效果报告同时观察 finding 解决和新增问题，不能只看原 finding 被关闭。

## 非目标

- 不重写整章或自动合并候选。
- 不在本任务中建立作者偏好学习；样本选择先使用显式配置。
