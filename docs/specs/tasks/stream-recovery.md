# 加固流式重试与恢复运行

## 任务目标

提高长时间生成面对限流、临时网络错误和服务端故障的恢复能力，同时保证自动重试不会把重复正文写入草稿。

## 重试边界

只有在尚未向调用方产生任何正文 delta 时，才允许对连接失败、429、可重试的 5xx 以及“流正常结束但正文为空”（例如只返回 reasoning 内容）进行有上限的指数退避。尊重 `Retry-After`，加入抖动，并沿用原 AbortSignal 的取消语义。

鉴权、参数、schema 不支持和其他不可重试 4xx 不做盲目重试。每次尝试记录原因、等待时间和 usage（若提供）。

## 流中断恢复

一旦已经输出正文 delta，原运行不得透明重试。失败时继续保存 partial 和失败状态；恢复必须创建具有新 runId 的运行，并明确使用哪种策略：

- 从原上下文重新生成独立候选；或
- 作者基于 partial 手工继续。

恢复运行不能假设上游会从断句处续写，也不能把两次输出直接拼接。原 partial 与恢复候选都不得自动成为正式正文。

## 验收

- 首个 delta 前的 429/临时 5xx/空正文能按上限重试，并遵守取消和 `Retry-After`。
- 不可重试错误只调用一次。
- 已输出正文后中断不会自动重发并拼接，partial 完整保留。
- 恢复产生新 runId 和独立候选，原运行终态不被篡改。
- 多次尝试的事件序号、终态事件和 usage 记录保持明确。
- 现有流式取消与恢复测试不回归。

## 非目标

- 不在本任务中实现透明的断点续传协议。
- 不用自动重试掩盖持续的配置或额度错误。
