# 把定稿证据检索接入写作上下文

## 任务目标

让配角回归、旧物重现、地点重访、伏笔推进和前文呼应自动获得相关定稿证据，而不是只有章节标题索引或依赖作者手工搜索。

## 召回流程

按以下顺序构造候选：

1. 从本章相关 OpenLoop、事实和关系变化直接定位证据；
2. 按人物、故事线、地点和时间过滤定稿索引；
3. 为人物回归、物品来源、关系变化和 `previousLink` 分别构造短关键词查询；
4. 合并去重，按任务相关性、证据质量、新近度和当前卷关联排序；
5. 应用 POV 可见性检查和全局证据预算。

不得把整份合同拼接成唯一长查询，也不得只取单一查询的 top N 后结束。

## 材料契约

证据材料使用 `finalized-history` 类别，并携带：

- 来源提交、章节、段落和证据 span；
- 检索理由与相关性/优先级；
- POV 可见性判断；
- 内容哈希与派生索引水位。

`Material` 和预算准入必须保留相关性排序。可选材料不能再按 `sourceId` 字典序决定裁剪顺序。

检索证据默认是可选材料，预算不足时记录省略原因；当前章安全必需信息不得伪装成检索证据后被省略。无法确认可见性的原文不进入 limited POV prompt，可以只返回安全的账本定位信息。

## 上下文规模

每个查询可以取少量候选，但最终注入采用全局去重和预算，不固定“所有查询各四段”。优先保留能回答当前写作问题的最小原文范围，必要时提供父块回读而不是整章注入。

同一章最多占用 2 个证据名额；近似重复（4-gram Jaccard 超过 0.6）的段落只保留一次。重复 beat 不得挤占其他章节的名额。

## 效果实验

使用 `retrieval: on | off` 做消融。纵向集分别报告应召回证据命中率、错误召回、POV 泄漏、正文呼应质量和额外 token；不能只报告最终文学评分。

## 验收

- 配角回归、旧物来源和伏笔推进至少各有一个自动召回场景。
- 注入段落均来自当前主线定稿提交，可精确回读原文。
- 预算超限时优先保留高相关材料，不被文件名字典序挤掉。
- 近重复段落只占一个名额，且任一章节不超过 2 个名额。
- 当前 POV 不可知的秘密原文不会进入 prompt；无法判断时不放行。
- 索引 stale/failed 时不使用旧检索结果。
- 检索关闭时保持现有生成路径，开关与材料清单写入运行记录。
- 纵向评测能说明召回是否改善，以及收益是否抵得上 token 和延迟。

## 非目标

- 不在本任务中增加 embedding 或模型 rerank。
- 不用检索摘要替代事实账本，不自动把召回段落升级为 Canon。
