# 按召回证据决定是否增加语义检索

## 启动条件

只有在长篇纵向集证明“结构化关系 + 中文关键词”对换说法的旧场景存在稳定、影响正文的召回缺口时，才启动本任务。若现有关键词与证据召回已满足需求，本任务保持不实施，不以功能完整为由加入向量。

启动报告必须列出具体漏召样本、现有查询、期望证据和正文影响。

## 实现边界

使用已配置模型服务的 OpenAI-compatible embedding 端点，配置独立 `embeddingModel`。向量与 chunk 内容哈希、模型、维度和主线水位一起存入 SQLite；不要求本地推理或独立向量数据库。

关键词与向量结果通过现有 RRF 思路融合，向量权重可配置。embedding 失败时保留可用关键词结果并明确标记降级，不破坏既有索引。

原文可见性、来源提交、证据回读、预算排序和 POV 规则完全复用现有检索路径，向量分数不得绕过这些约束。

## 重建与版本

更换 embedding 模型或维度时创建新向量版本，不混算旧向量。重建可按主线重放并记录失败；向量是派生数据，删除后不影响正文和事实账本。

## 效果验收

在同一漏召集和完整纵向集上比较：

- 关键词与结构化召回；
- 关键词 + 向量 RRF；
- 可选的重排策略。

至少证明应召回证据改善，且错误召回、POV、安全和接受章节成本没有不可接受的退化。若只有排名变化而正文无收益，不默认启用。

## 非目标

- 不引入独立向量平台、强制 embedding key 或本地大模型推理。
- 不把 cosine 分数当作证据相关性或可见性的替代判断。
