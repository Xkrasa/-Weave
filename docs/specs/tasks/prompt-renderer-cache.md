# 实验任务书渲染与缓存友好分层

## 任务目标

在不丢失事实与约束的前提下，比较不同 prompt 表达对正文效果的影响，并让实际发送的消息前缀更适合 provider 缓存。

## 可切换渲染器

保留结构化内部材料，增加至少两种完整渲染器：

- `json`：接近现有行为，作为对照；
- `mission`：自然语言任务书，使用清晰章节和约束列表。

可以增加 Markdown 变体，但不得一次发送同一材料的 JSON 与自然语言双份。mission 至少区分本章委托、故事任务、人物与信息边界、写作方式、收束要求和定稿证据。

硬约束、禁止事项、POV 边界和证据引文必须使用明确列表或结构块，不能为了提高“散文感”而模糊。

## 消息分层

按真实变化频率排列：

1. 写作协议、StoryPromise、长期风格与 Canon；
2. 当前卷规划、卷级方法和有界卷摘要；
3. 本章合同、POV 当前状态、检索证据、上一章衔接与近期计划。

卷摘要和按章路由的方法不得被错误宣称为永久稳定前缀。每层保留独立哈希，同时保留完整上下文哈希用于审计。

## 缓存验证

`contextHash` 只用于 Weave 内部身份，不作为缓存命中证据。适配器按 provider 能力使用自动缓存或显式缓存断点；不支持时只完成消息分层，不伪报收益。

运行记录保存实际请求层哈希和 provider 返回的缓存 usage（若提供），结合延迟与费用判断效果。

## A/B 实验

使用 `promptRenderer: json | mission` 独立对比，不与检索或多候选同时改变。比较合同兑现、事实错误、正文盲评、token、缓存命中和延迟。不预设自然语言一定优于 JSON。

## 验收

- 两种渲染器表达相同权威材料，无字段静默丢失或新增事实。
- mission 中硬约束、POV 禁止信息和证据范围仍清晰可机读审计。
- 只有章级材料变化时，长期稳定前缀保持逐字节一致。
- 缓存支持与不支持的 provider 都有明确行为，不以内部哈希冒名缓存命中。
- A/B 报告能单独归因渲染器影响，并保留成本与延迟。

## 非目标

- 不承诺所有模型都偏好任务书或所有服务商都支持缓存。
- 不因缓存复用跨越材料版本、POV 或主线水位。
