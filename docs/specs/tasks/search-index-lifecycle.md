# 将检索索引纳入主线水位

## 任务目标

让检索索引随定稿、回改和重建保持一致，为生成自动检索提供可信前提，消除“每次写作前都要人工记得重建索引”的隐式操作要求。

## 实现决策

将检索索引视为有独立水位的派生投影，至少记录所选 `mainlineRevision`、最后应用的提交、状态和失败原因。

定稿成功后同步应用该章当前提交；回改只替换受影响章节的索引内容，不重写历史提交。同步失败不回滚已经合法的正文和提交，但必须将索引标为 stale 或 failed。

依赖自动检索的写作在索引非 current 时不得静默使用旧数据，应返回可执行的重建提示。人工搜索延续同样的 stale 拒绝行为。`doctor` 和 `status` 能报告索引水位及失败原因。

全量重建继续支持从权威正文和提交确定性生成索引。外部正文漂移仍走现有完整性流程，不能借索引同步静默接受。

## 性能边界

单章定稿不得默认全量扫描并重写整本书索引。单章应用与全量重建可以使用同一事务内写入逻辑，避免两套索引语义。SQLite 事务同时更新内容与水位，失败不得留下半新半旧状态。

## 验收

- 新章定稿后，无需手动 `index rebuild` 即可检索新正文，索引水位等于当前主线。
- 回改旧章后，被替换段落不再按旧提交召回，新段落可召回。
- 索引同步失败时提交仍完整，状态明确，自动检索写作被阻断并提示恢复方式。
- 删除索引后全量重建的结果与删除前一致。
- 150 章回归项目中，单章定稿不执行全量索引重建。
- 现有 CLI/UI 搜索和 54 项工程测试不回归。

## 非目标

- 不在本任务中把检索材料注入生成上下文。
- 不引入 embedding、外部向量数据库或新搜索框架。
