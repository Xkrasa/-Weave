# 马良写作（maliangwriter.com）功能与实现流程逆向调研

> **状态（2026-11-07）**：本文的可用结论（§4.2 抽取规矩、§4.3 装配表、§五对照）已并入 `docs/plans/maliang-optimization-plan.md` 的批次方案；后续实施以该方案为准，本文保留作为事实与证据记录。
>
> 检索日期：2026-11-06。本文是外部产品的黑盒调研笔记，不是规范、不是 Canon，也不构成对 Weave 的强制改动。文中「实现流程」分两档标注：**〔原文明确〕**为官方页面直接写明，**〔推断〕**为从公开复述中反推，未经验证。

## 一、调研边界：逆向能得到什么、得不到什么

可观测面：首页与 6 个功能页、`/docs` 26 篇官方教程（2026-03-21 ~ 2026-06-22）、`/blog` 112 篇文章（2026-03-01 ~ 2026-10-13）、HTTP 响应头、首页内联样式。

**无法获得**：服务端 Prompt 文本、抽取用的 JSON schema、档案存储结构、真实检索方式（向量/关键词）、上下文裁剪算法、重试参数（次数/退避/阈值）、模型清单与路由表。产品是闭源 SaaS，所有「实现」都只到机制名层面；博客中「语义记忆」「自动切换」等属于营销表述，无实现佐证。

**技术栈可观测证据**：`Server: nginx` + `EO-Cache-Status: HIT`（腾讯 EdgeOne CDN）；首页 163KB 静态 HTML；内联 `data-initial-theme` 与 shadcn/ui 风格 HSL 三元组变量（`--primary`、`--radius: 0.875rem`），字体按 `unicode-range` 切片异步加载。前端框架未能从首屏检出标记，不做断言。应用端（登录后的编辑器）未探测。

## 二、产品定位与差异主张

- 一句话：面向**长篇小说连载**的**人机协作**平台，接前文续写、按章维护档案、正文改动可逐段对比。
- 明确反「一键成书」叙事：卖点句为「故事往哪走，由作者决定」；对「去 AI 味能否过检测」直接回答**不能保证**，是同类营销里少见的克制表述。
- 立论用一句话概括：*写一章漂亮正文不难，难的是几十万字后还接得住前情、人物还像自己、文字还像你。*
- 商业模式：注册送 1000 积分 + 问卷 400 积分（宣称约 30 万字），订阅制，导入旧稿**必须有效订阅**（官方文档明示无游客旁路）。

## 三、功能与工具清单

| 模块 | 对外宣传的能力 |
| --- | --- |
| AI 续写 | 读上一章结尾 + 本章章纲 + 本章出场人物/设定当前档案，按前文句长、段落、口气续写 |
| 故事档案 | 每章写完自动抽取：本章档案、角色档案、设定档案、**数值总账**、**时间线**、伏笔 |
| 正文与改稿 | 章节诊断（多维打分 + 正文取证）、错别字/重复句/人名异写、去 AI 味改写、章尾诊断、文风比对 |
| 角色与世界观 | 人设写「遇事怎么想、怎么说」而非性格标签；设定集中管理，变化记入档案 |
| 三级大纲 | 总纲 → 卷纲 → 章纲，「没要求的层级不乱建」 |
| 爆款仿写 | 参考番茄热门作品，提供「仿写设定 / 大纲 / 正文 / 架构」四个入口 |
| 多智能体 | 主助手（商量剧情）、专职写手、档案员、按需的研究/审稿角色 |
| 渐进式披露 | 设定可隐藏、按卷逐步开放给 AI |
| 自定义智能体 | 给每个 AI 配人设与专属知识库 |
| 质量工具 | 全书一致性体检、AI 率检测（接第三方并按次计费）、节奏分析、章节基准对比、封面/立绘生成 |
| 九步开书 | 立项 → 角色设定 → 卷纲章纲 → 黄金前三章 → 续写第 4 章 → 第一卷 → 精修第 2 章 → 去 AI 味 → 盘点全书 |

## 四、逆向出的实现流程

### 4.1 主链路〔原文明确〕

```
章纲（已批准）
  → 装配「前情包」：上一章结尾 + 本章章纲 + 出场人物/设定的当前档案
                    + 前几章的本章档案/伏笔/书中时间线 + 前文样本（量化风格）
  → 写手生成正文（流式）
  → 后台自动整理本章档案（默认开，可关，作者不用等）
  → 冲突项进「待确认」队列，交作者裁决
  → 作者改稿（逐段 diff，保留/还原；整轮撤销；可另起分支）
  → 下一章重复（档案是累计状态，不是上一章增量）
```

三个关键设计选择：

1. **档案按章组织、按当前章取用**，而非全书一份总档；否则长篇必然全量塞入。
2. **档案是「正文的投影」，不是设定集的副本**；设定集 = 计划态，档案 = 实际态，两者续写前**合并注入**。
3. **生成前拦截 + 生成后报告**：章纲与正文不一致在续写前提示；目录调整导致的章纲错位按「章名+章号+剧情」三重线索匹配，而非按序号硬对。

### 4.2 档案抽取规则〔原文明确〕

四条硬规矩，是整个产品里最有信息量的部分：

- 每条记录必须能在正文里找到依据；**正文没写的不补、不猜**。
- **推不出来的数不编**：数值对不上时进「待确认」，不凑结余。
- 正文与既有设定冲突时**列出原句**，由作者决定以哪边为准，**不擅自改正文**。
- 章节被修改后该章档案**标记过期并重整**；拆/并/插/跨卷移动时档案与伏笔的**引用跟着走**（引用而非拷贝），删章进回收站。

数值走「**变化 → 结余**」逐章累计；时间线记录书中日期并**标注是正文写明的还是推算的**。老书补建全书档案先**估算积分 → 用户确认 → 可随时中断**。

### 4.3 上下文装配（最有参考价值的一块）〔原文明确，数值来自官方文档〕

写作页右侧 AI 助手 → `AI功能管理` → `上下文` 标签页，**按单本小说独立存储**：

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| 平台默认上限 | **60,000 token** | 与实际发送内容一致，非估算；另显示所选模型自身窗口上限，两条线分别飘红 |
| 总开关 | 开 / 关 | **关 = 回退「精简装配」**（只给名称和摘要），二元降级而非分级裁剪 |
| 小说架构 | 按字段勾选 | 可剔除「发布渠道」等对正文无用的字段 |
| 设定 / 角色 / 悬念 | **完整 / 仅名称** | 「仅名称」被官方点名为省 token 的大头；条目数动态显示（如 设定 22 / 角色 16） |
| 大纲（全局摘要） | 开 / 关 | 需要顾全大局时开 |
| 章纲/卷纲 | **默认关闭** | 范围可选 `本卷` / `最近 N 章`（配图示例 N=10，非出厂默认）/ `指定范围`；可勾「同时装配对应卷纲」 |

官方给了三套配比：大批量写正文（设定角色仅名称 + 关悬念 + 仅本卷）、关键章节（全完整 + 最近 N 章 + 卷纲）、纯聊创意（关总开关）。**超限处理**：超 60k 引导去开「最大上下文」，不开启则「超出部分自动压缩」；超模型窗口只能精简维度或换模型。裁剪优先级未公开。

### 4.4 稳定性机制〔C 级，来自官方博客，无实测数据〕

- 自称 **7 个专业 Agent + 1 个协调 Agent**；协调者持有全局状态，其余按职责隔离。
- 任务顺序固定串行：大纲 → 分卷 → 章节蓝图 → 正文 → 一致性检查。
- 三层兜底：网络超时退避重试 → 首选模型不稳自动切备用（用户无感）→ 上下文超限自动摘要压缩。
- 取消后：已生成内容保留 + 进度快照持久化 → 可断点续写或重来。
- 纠错 Agent 故障隔离，恢复后自动补做。
- 缺失：幂等键、重复写入防护、崩溃（非自愿中断）恢复、并发与超时参数——文章本身未作答。

### 4.5 文风控制〔原文明确〕

不是形容词，是**从正文量值**：句长、段落长度、对话占比、标点习惯 → 给数值区间 → 续写落在区间内。再叠三层：叙述口气（把主角当场判断写进叙述）、体裁轻重（轻松书可贫嘴、严肃书不硬塞笑点、轻松书遇沉重场面也要郑重写）、偏好累积（改过的地方、退回意见带入下一章）。章尾则**按题材统计热门作品的章尾类型**给建议，而非一律删升华。

## 五、与 Weave 的逐项对照

| 能力 | 马良做法 | Weave 现状 | 结论 |
| --- | --- | --- | --- |
| 事实账本 | 档案 + 变化记录，无版本模型 | `story-ledger.ts` 事实带 `validFrom/validTo/supersedes/evidence`，可回溯到定稿 | **Weave 更强**，不照搬 |
| 角色认知 | 档案里记人物状态 | 独立 `LedgerBelief` + `attitude`（knows/believes/suspects/misbelieves/doubts）+ `checkKnowledge` POV 门禁 | **Weave 更强** |
| 数值总账 | 「变化 → 结余」逐章累计，对不上进待确认 | 事实只有 `predicate/object` 字符串，无算术累计与结余校验 | **缺口**，值得补 |
| 设定可见性 | 可隐藏设定、按卷渐进开放 | `canon/*.md` 作为 `required` 材料**每章全量注入**，无按卷披露、无剧透门禁 | **缺口**，且是成本与剧透双重问题 |
| 上下文降级 | 总开关二元降级 + 每维度「完整/仅名称」 | 按 `relevance → priority` 排序 + `required` 保留，无可降级的「仅名称」档 | **缺口**，缺的是粒度而非预算算法 |
| 抽取冲突处理 | 无法推定的进「待确认」，保留原句交作者裁决 | 证据不合法则整条 `rejected` 丢弃，仅 `waived/ignored` 可豁免 | **方向不同**：Weave 不静默通过，但也静默丢弃 |
| 文风量化 | 从正文自动量出区间 | `methods.ts` 会统计句长/对话占比并对照 `style.json`；但区间是作者**手填**的 | 半缺口：只需补「从本人定稿推导区间」 |
| 章尾建议 | 按题材统计热门作品章尾类型 | `endingStrategy` 是自由文本 + `content-check` 正则 | 可选增强，非核心 |
| 多智能体 | 7+1 Agent，串行状态机 | 用**阶段**实现同一分工：`writing`（写手）/ `extraction`（档案员）/ `review`+`effect-review`（审稿）/ `planning`（策划），经 commit 账本串接 | **不需要改成多 Agent**；阶段化 + 账本可审计性更好 |
| 三级大纲 | 总纲/卷纲/章纲 + 章纲写清每场推进 | `planning.ts` 四级 kind + `outline.ts` 章纲候选/批准/应用 | 已覆盖 |
| 改稿审阅 | 逐段 diff + 保留/还原 + 撤销本轮 + 另起分支 | `revisions.ts` 段级候选 + `merge` 逐段合并 + `recheck`；`versions/` 留历史 | 已覆盖，撤销语义可再确认 |
| 仿写 | 参考作品「仿写设定/大纲/正文/架构」四入口 | `deconstruct.ts` 拆书 + `methods.ts` 方法卡，且**不把参考原文注入正文** | Weave 边界更严，保留 |
| 计费/积分 | 积分制 + 成本可视化 | `usage.ts` + `runs/` 记录模型、参数、成本 | 已覆盖 |

## 六、值得借鉴的部分

取舍与落点已抽出独立清单：`borrowable-designs-from-maliangwriter.md`（同目录，含证据标注、Weave 具体文件位置、风险与验收）。本文只保留「它有什么、怎么做、Weave 现状如何」的事实对照，不在此重复实现建议。

## 七、明确不采纳

- **多 Agent 数量当卖点**：Weave 的阶段化已实现同等分工，且经 commit 账本可审计；引入协调 Agent 会与「作者权威不可越权」「单次生成可解释」冲突。
- **积分制与订阅绑定导入**：与本地优先、无模型也能写作的定位相悖。
- **把参考作品原文段落注入生成上下文**：`goal-and-requirements.md` 已列为非目标。
- **承诺「过 AI 检测」**：对方自己也不承诺；Weave 不做此类声明。
- **超限自动静默压缩**：对方文档承认超限部分「自动压缩、AI 可能看不全」；Weave 现有 `capacity-conflict` 显式失败更安全，不退回静默裁剪。

## 八、待验证

- 档案注入的 token 预算与优先级（官方未公开，只能从 60k 上限与维度开关反推）。
- 「待确认」队列是否影响后续注入（若待确认项被排除，等于事实缺口；若包含，等于未裁决信息进入生成）。
- 按卷归档的具体边界（第几卷起归档、回归如何放回）。
- 跨模型 fallback 的切换阈值与切回条件。
- `borrowable-designs-from-maliangwriter.md` 中各借鉴项在 Weave 侧的成本/收益，需用 `bench/` 现有评测流程做 A/B，而非直接改默认行为。
